# wt: マージ済みの worktree を整理する

GitHub の PR が `origin` の既定ブランチに取り込まれ、指定時間以上更新されていない linked worktree を削除します。**worktree のディレクトリと登録は消えますが、ブランチは残ります。**

```sh
giclean wt -d 3 --dry-run --explain  # 候補と、残す理由を確認
giclean wt -d 3 --interactive        # 候補から選び、yes で削除を確定
giclean wt -d 3                      # 確認なしで削除
giclean wt -h 12 --dry-run            # 待機時間を12時間に指定
```

Git 2.47 以降と、認証済みの [GitHub CLI (`gh`)](https://cli.github.com/) が必要です。`origin` は github.com の HTTPS / SSH URL に対応します。GitHub Enterprise・SSH ホストの別名・他サービスは対象外です。

## 何が消える・残るか

対応する PR の先端・ブランチ・マージ先が一致し、変更が最新の既定ブランチへ取り込まれたことを確認できるものだけが対象です。通常マージ・squash・fast-forward に対応します。PR を介さない取り込み、PR と一致しない改名・追加コミット、日時や取り込みを確認できないものは残します。

待機時間は **PR のマージ時刻と、最後のファイル更新・Git 操作のうち新しい方**から数えます。月曜にマージ、水曜に最後の操作をした場合、`-d 3` なら水曜から72時間後が対象です。

次は削除しません。

- 主 worktree、現在の worktree、ロック済み、消失した登録。
- `main` / `master` / `production` / 既定ブランチ。detached HEAD は既定で残します。
- 未コミット変更、未追跡ファイル、ignored ファイルがあるもの。
- `assume-unchanged` / `skip-worktree` が設定されたファイル、進行中の Git 操作やロックがあるもの。
- 更新時刻が未来のもの、検査中に状態が変わったもの、エージェントの利用状況を安全に確認できないもの。

**現在の Codex 保護では、対象の Codex home があるだけで全 worktree を保持します。終了済みの履歴しかなくても同じです。** 詳しくは [Codex 保護](../agents/codex.md)を参照してください。

読み取りだけの利用や未保存の編集は更新として検出できません。別プロセスが使用・書き込み中の worktree では実行しないでください。確実に残すには `git worktree lock` を使います。

## オプション

| オプション | 用途 |
| --- | --- |
| `-d` / `--days`、`-h` / `--hours` | 待機時間。正の整数でどちらか一つを指定。明示した[設定ファイル](../configuration.md)の値も利用可能 |
| `--dry-run` | 削除せず候補を確認 |
| `--explain` | 候補・保持の理由、確認できた時刻、実行結果を表示。単独では削除を止めない |
| `--interactive` | 端末上で番号をスペース区切りで選択。空入力・`q`・EOF・確認の拒否でキャンセル |
| `--include-detached` | 対応 PR の先端またはマージ結果と HEAD が完全一致する detached worktree も検査 |
| `--allow-ignored <path>` | 削除してよい ignored ファイルの worktree 相対パス。繰り返し指定可能 |
| `--format json` | [JSON 出力](../json-output.md) |
| `--help` | ヘルプ。`-h` は時間指定 |

`--interactive` は `--dry-run`・JSON 出力・パイプと併用できません。選択や追加オプションは、取り込み確認・待機時間・その他の保護を解除しません。

### ignored ファイルを許可する場合

```sh
giclean wt -d 3 --allow-ignored node_modules --dry-run --explain
```

指定したディレクトリ内の ignored ファイルはすべて削除してよい、という指定です。**再生成できる内容だけに限定し、個人データを含む広いパスは指定しないでください。** 未追跡ファイル、許可外の ignored ファイル、入れ子の Git リポジトリや検査できない内容があれば残します。symlink 経由の指定も許可しません。

`--include-detached` と併用できますが、`batch wt` では使えません。削除済みの ignored ファイルは履歴から復元できません。[復旧の限界](../audit-history.md#復旧可能な範囲)を確認してください。

## 出力と失敗時の動作

通常の出力は `candidate: <path>`（候補）、`<path>: deleted`（削除成功）、`<path>: failed (<reason>)`（失敗）です。理由や診断は英語です。`--explain` なしで対象がなければ、結果は出力しません。

- dry-run でも GitHub・リモート照会を行います。認証・照会・初期検査に失敗した場合は削除を始めません。
- 自動 fetch はしません。最新コミットが未取得と案内されたら、`git fetch origin` 後に再確認してください。
- 削除直前にも状態を再検査します。状態が変わった対象は残し、再検査自体に失敗した場合は以降を中止します。
- 個別の削除失敗は報告して残りを処理します。**成功済みの削除は取り消しません。** 同時操作を完全には防げないため、他の処理と並行して実行しないでください。

終了コードは正常・対象なしが `0`、照会・検査・削除などの失敗が `1`、引数不正が `2` です。進捗と診断は標準エラー、結果は標準出力に出ます。

実行履歴を残したい場合は [実行履歴](../audit-history.md)を参照してください。既定では保存しません。
