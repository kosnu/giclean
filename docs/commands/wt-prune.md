# wt prune: 消失した worktree の登録だけを整理する

```sh
giclean wt prune -d 3 --dry-run  # 登録の削除候補を確認
giclean wt prune -d 3 --execute  # 確認なしで登録を削除
giclean wt prune -d 3 --skip-retained --dry-run  # 保留分を除いて候補を確認
```

`-d` / `--days` または `-h` / `--hours` で正の待機時間を指定し、`--dry-run` か `--execute` を毎回明示します。待機時間は登録情報の最終更新から数え、PR のマージ日時は使いません。

## 何が消える・残るか

Git が `prunable` と判断した登録だけが対象です。**実体のファイルやブランチ、コミットを直接削除するコマンドではありません。** 有効な登録とロック済みの登録は残します。GitHub 接続や `gh` は不要で、fetch もしません。

次の登録は保留します。

- 指定期間に満たないもの。
- 登録が参照するコミットや履歴を、残すブランチなどからたどれると確認できないもの。squash で内容だけ取り込まれていても保留します。
- ステージ済み変更、欠落・破損・読み取り不能の情報、進行中か不明な Git 操作があるもの。
- 検査結果に食い違いがあるなど、安全を確認できないもの。

**通常は、候補に1件でも保留があれば何も削除しません。** `--skip-retained` を付けると、保留理由を表示し、それ以外の安全確認できた登録だけを整理します。実行する場合は同じ指定に `--execute` を付けてください。待機期間や安全条件を無視する指定ではなく、登録構造や検査結果に矛盾があれば全体を停止します。作業フォルダが残っていても `.git` が失われた登録は対象になり得ますが、フォルダ内のファイルは削除しません。

通常の sparse-checkout 設定・パターンや、Codex のローカル環境設定への参照だけなら対象にできます。fetch しただけで他に保存先がないコミットは引き続き保留します。外部設定の読み込みや別パスを指定する worktree 設定、分割インデックスなど、検証に対応していない情報があれば引き続き保留します。保留を解除するために設定ファイルを手で消さないでください。

## 保留・失敗したら

- 期間未満なら待ってから再確認してください。
- 未保全のコミットがある場合は、必要な作業かを調べ、残すブランチなどに保存・検証してから再実行してください。自動退避はしません。
- 登録が壊れている場合は、Git の修復手順を個別に検討してください。
- `--skip-retained` の実行途中で停止した場合は、一部の登録が既に隔離・削除済みのことがあります。表示された回復場所を確認し、別の Git 操作を止めてから個別に復旧してください。新しい登録を上書きしないため自動復元はしません。
- 同時操作を完全には防げません。実行中は別プロセスの Git 操作や worktree の作成・移動を止めてください。実行失敗時も、再実行前に登録の現状を確認してください。

削除した登録情報のバックアップは作りません。[復旧の限界](../audit-history.md#復旧可能な範囲)を確認してください。

単一リポジトリのテキスト出力のみです。`batch`・JSON 出力・対話選択には対応しません。オプションは `giclean wt prune --help` で確認できます。

旧名 `giclean wt-prune` も同じ動作をしますが、非推奨警告を標準エラーに表示します。新しい呼び方には `giclean wt prune` を使ってください。
