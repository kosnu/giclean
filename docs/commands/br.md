# br

`origin` の最新の既定ブランチにマージ済みのローカルブランチを削除します。

## 使い方

整理したいリポジトリの作業ツリー内で実行します。サブディレクトリや linked worktree からも実行できます。

```sh
giclean br --dry-run  # 削除候補を確認
giclean br            # 確認プロンプトなしで削除
giclean br --help
```

`--dry-run` でも候補の判定に必要なリモート照会は行います。ローカルで保護対象を除いた時点で候補がなければ、通信せず正常終了します。

引数なしの `giclean` はヘルプを表示します。ブランチ整理には `br` を指定してください。全体のヘルプは `giclean --help`、バージョンは `giclean --version` で確認できます。

## 出力と終了コード

| 出力先 | 内容 |
| --- | --- |
| 標準出力 `candidate: <branch>` | dry-run の削除候補。候補ゼロなら出力なし |
| 標準出力 `deleted: <件数>` | 通常実行で削除できた件数 |
| 標準エラー出力 | 実行直後・通信開始前・判定時の進捗、エラー |

標準エラー出力が端末につながっている場合は、スピナーと経過時間で処理中の段階を表示します。完了した段階は `✔`、失敗した段階は `✘` に変わります。通常実行では削除済み件数、dry-run では最後に候補件数も表示します。

リモート照会中は、Git の認証情報入力や SSH のパスフレーズ入力を妨げないよう、状態を一行表示してスピナーの再描画を停止します。Git の標準エラー出力は端末に引き継ぎ、照会完了時に経過時間を表示します。

Git の診断メッセージが出た場合は、その段階のスピナー更新を止めてメッセージを表示します。標準エラー出力をファイルやパイプへリダイレクトした場合、または `TERM=dumb` の場合は、従来の行単位の進捗表示になります。標準出力の `candidate:` / `deleted:` はどちらの場合も同じ形式です。

| 終了コード | 意味 |
| --- | --- |
| `0` | 正常終了。対象なしも含む |
| `1` | リポジトリ・通信・判定・削除などの失敗 |
| `2` | 引数不正 |

## 判定と保護

1. ローカルブランチの先端、現在のブランチ、worktree 使用状態を記録します。
2. 使用中のブランチ、`main` / `master` / `production`、symbolic なローカルブランチを除外します。残りがなければ通信せず終了します。
3. 設定済みの `origin` に対して `git ls-remote --symref --exit-code origin HEAD` を一度実行し、既定ブランチ名と最新コミット ID を取得します。
4. 最新コミットがローカルにあることを確認します。未取得なら `git fetch origin` を案内して停止します。自動 fetch は行いません。
5. そのコミットの祖先に先端が含まれるブランチだけを対象にします。リモートの既定ブランチ自体も保護します。
6. 通信後に先端や使用状態が変わったブランチ、新しく作られたブランチは対象から外します。各ブランチへの操作直前にも再確認します。
7. dry-run では候補を表示し、通常実行では判定済みブランチを `git branch -D --quiet -- <branch>` で削除します。ブランチに付随する Git 設定や reflog の処理も Git が行います。

判定基準は最新のリモート HEAD です。ローカルの `origin/HEAD` や `origin/main` のキャッシュには依存しません。リモート名は `origin` 固定です。

通常の OpenSSH 接続は最後の利用から60秒間再利用します。参照情報のキャッシュは行わず、実行ごとに最新のリモート状態を照会します。適用条件や明示的な SSH 設定の扱いは [SSH 接続の設計](../design.md#ssh-接続)を参照してください。

通常の Git 履歴に基づく判定です。squash / rebase 後のパッチ比較や PR 照会による補完は行いません。未マージの先端は保持します。ローカルの replacement object は判定に使用しません。partial clone の不足オブジェクト取得も無効にしています。

## 失敗時の動作と制約

- リモート照会失敗、空のリモート、symbolic でないリモート HEAD、既定ブランチや最新コミットを特定できない場合は削除前に停止します。
- bare リポジトリ内では実行できません。UTF-8 で解釈できないブランチ名など、状態を正確に取得できない場合も停止します。
- 再確認から削除までを単一の原子的操作にはしていません。Git 自身も worktree 使用中のブランチの削除を拒否しますが、他プロセスによる同時更新を完全には防ぎません。
- 削除途中で失敗した場合、成功済みの削除は取り消しません。削除コマンドの失敗は標準エラーへ表示し、残りの候補を処理して成功件数と終了コード `1` を返します。
- 操作直前の再確認に失敗した場合は、以降の削除を中止して、それまでの成功件数と終了コード `1` を返します。

Git と SSH の扱いは [設計](../design.md)、検証方法は [開発手順](../../CONTRIBUTING.md)を参照してください。
