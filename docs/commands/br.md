# br: マージ済みのローカルブランチを整理する

リポジトリ内で実行します。サブディレクトリや linked worktree からも使えます。

```sh
giclean br --dry-run --explain  # 削除候補と、残す理由を確認
giclean br --interactive        # 候補から選び、yes で削除を確定
giclean br                      # 確認なしで削除
```

## 何が消える・残るか

`origin` の最新の既定ブランチに取り込まれたローカルブランチが対象です。通常のマージに加え、squash などで変更した全パスの内容・権限が、既定ブランチの現在または過去の同一時点で完全一致するものも含みます。

**過去に完全一致していれば、その後に変更が取り消されていても対象です。** 同じ内容が独立した操作で作られた場合も対象になります。一部だけの取り込みや、未取り込みの追加変更があるものは残します。

次は削除しません。

- `main` / `master` / `production` と、`origin` の既定ブランチ。
- 現在または他の worktree で使用中のブランチ。
- 取り込み済みと確認できないもの、検査中に先端や使用状態が変わったもの。

リモートブランチや worktree のディレクトリは削除しません。削除したローカルブランチの設定・reflog は失われます。[復旧の限界](../audit-history.md#復旧可能な範囲)も確認してください。

## オプションと出力

| オプション | 用途 |
| --- | --- |
| `--dry-run` | 削除せず候補を確認 |
| `--explain` | 候補・保持の理由と実行結果を表示。単独では削除を止めない |
| `--interactive` | 端末上で候補の番号をスペース区切りで選択。空入力・`q`・EOF・確認の拒否でキャンセル |
| `--format json` | [JSON 出力](../json-output.md) |
| `--help` | ヘルプ |

`--interactive` は `--dry-run`・JSON 出力・パイプと併用できません。選択しても保護条件は解除されず、削除直前に変化した対象は残します。

通常の出力は `candidate: <branch>`（候補）、`<branch>: deleted`（削除成功）、`<branch>: failed (<reason>)`（失敗）です。理由や診断は英語です。`--explain` なしで対象がなければ、結果は出力しません。

## 失敗したら

- dry-run でも必要なリモート照会を行います。通信できない・既定ブランチを特定できない場合は削除を始めません。
- 自動 fetch はしません。最新コミットが未取得と案内されたら、`git fetch origin` 後に再確認してください。
- bare リポジトリでは使えません。その他、状態を正確に取得できない場合も処理を中止します。
- 個別の削除失敗は報告して残りを処理します。削除直前の再検査に失敗した場合は以降を中止します。**成功済みの削除は取り消しません。**
- 同時更新を完全には防げません。別プロセスの Git 操作と同時に実行しないでください。

終了コードは正常・対象なしが `0`、照会・判定・削除などの失敗が `1`、引数不正が `2` です。進捗と診断は標準エラー、結果は標準出力に出ます。

実行履歴を残したい場合は [実行履歴](../audit-history.md)を参照してください。既定では保存しません。
