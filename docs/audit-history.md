# 実行履歴と復旧の限界

履歴は既定で **無効**。必要な実行にだけコマンドの前へ指定する。

```sh
giclean --audit-log /private/logs/preview-001.jsonl br --dry-run
giclean --audit-log /private/logs/cleanup-001.jsonl wt -d 5
```

親ディレクトリは自分で用意し、他ユーザーが書き換えられない保存先を選ぶ。
削除対象の Worktree 内を保存先にしない（ログ自体を失うおそれがある）。
ファイルは毎回新規作成する（Unix 権限 `0600`）。既存ファイル、同名の
シンボリックリンク、作成不可の保存先は上書きせず、削除前に失敗する。
連続実行には別名を指定する。指定を省略すれば履歴は保存されない。
自動ローテーションや送信はしない。保存期間と削除は利用者が管理する。

JSON Lines の `schema_version: 1` には開始時刻、コマンド種別、dry-run 指定、
終了時の成功状態を記録する。`dry_run_token_present` は引数中に `--dry-run`
というトークンがあったことだけを示す（値として使われる場合もある）。
読み取り専用の保証ではなく、実際の処理結果は outcome を確認する。`br` / `wt` では実行結果（candidate / deleted /
failed / skipped / not_attempted）と Git オブジェクト ID を残す。
パス、リポジトリ名、ブランチ名、リモート URL、セッション内容、ファイル内容、
任意の引数・エラー本文は残さない。ただしオブジェクト ID もリポジトリを
知る人には照合可能なので、公開ログや共有フォルダーへ置かない。
`batch` / `wt prune` はコマンド全体の成否のみで、対象別結果はない
（`target_results_available: false`）。成功だけでは削除件数や保留なしを意味しない。
`wt prune` のログのコマンド種別は互換性のため `wt-prune` のままです。
対象別詳細が必要なら各リポジトリで `br` / `wt` と `--explain` を利用する。

開始レコードは処理前に同期する。中断・電源断や終了時の書き込み失敗では
開始だけが残ることがある。終了ログの失敗は非ゼロで報告するが、既に行われた
削除は戻らない。**再実行前に現状を調べること**。ログは監査の補助であって
完全なジャーナル・トランザクション・バックアップではない。

## 復旧可能な範囲

- ブランチ削除：対象オブジェクトがまだ存在すれば、記録した ID を
  `git cat-file -t <OID>` で確認し、適切な名前で `git branch <new-name> <OID>`
  として参照を再作成できる。元の名前・追跡設定・reflog は復元しない。
- Worktree 削除：オブジェクトが残っていれば、空いた別パスへ
  `git worktree add --detach <new-path> <OID>` で追跡済み内容を再展開できる。
  削除済みの ignored ファイル、キャッシュ、元の index やセッション状態は戻らない。
- `wt prune`：削除された登録メタデータのバックアップはない。オブジェクトの
  存在・参照を調べ、必要なら新しい Worktree を作る。元登録の復元ではない。
- Git GC 等で失われたオブジェクト、未コミット内容や外部データは履歴から復元できない。

復旧コマンドは例であり自動実行しない。既存の名前・パスを上書きせず、
必要なコミットを実行前に別参照や独立バックアップで保持する。

`--config PATH` と併用するときは、両方ともサブコマンドの前に指定する。
順序はどちらでもよい（各オプションは一度だけ）。設定の読み取り・検証と
ログの新規作成が完了するまでクリーンアップを開始しない。

```sh
giclean --config settings.conf --audit-log /private/logs/run-002.jsonl wt --dry-run
giclean --audit-log /private/logs/run-003.jsonl --config settings.conf wt --dry-run
```

サブコマンド以降は通常の CLI 引数として解釈する。値や `--` 以降のパスを
グローバルオプションとして抜き取らない。

`br --interactive` / `wt --interactive` とも併用できる。選択後の実行結果を
同じ履歴に記録し、選択前の候補一覧を削除結果として記録しない。
キャンセル時は正常終了と空の結果になり、削除成功を意味しない。
ターミナルがない場合は失敗を記録して削除せず終了する。
