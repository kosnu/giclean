## 条件

- 比較元は 49a213b の実行ファイル。変更後は [SSH 接続共有](design.md#ssh-接続)を自動適用する実装。
- ローカル18ブランチ、うち16本が worktree 使用中。削除候補は両版とも0件。

全14回（ウォームアップを含む）が正常終了し、各回でリモート照会を1回行ったことを Git のトレースで確認しました。候補は一致し、ブランチ先端・HEAD・worktree 構成・作業差分も変わっていません。計測終了後に、検証で使用した接続を終了しました。

接続共有は参照情報をキャッシュしません。再利用中にリモートが更新された場合も、最新のコミットを取得できるか検査し、未取得なら削除前に停止する結合テストを追加しています。

この結果は候補0件・同じネットワークでの実測であり、削除処理の速度や他の環境での所要時間を保証するものではありません。60秒間利用がなければ接続が終了するため、その後の実行は再び初回接続になります。

## squash 完全一致判定の一括処理

2026年11月3日 JST、squash 完全一致判定の導入直後と、一括処理への変更後を比較しました。上の SSH 接続共有の比較とは別の測定です。

### 条件

- macOS / Apple Silicon、Git 2.54.0、Rust 1.89.0 のリリースビルド。
- 一時リポジトリとローカル bare origin を使用。SSH や外部ネットワークの待ち時間は含みません。
- 共通の1,000ファイルと、既定ブランチに追加された100パスを用意。未マージと squash 済みの各先端は共通祖先から1パスを追加し、それぞれ未取り込みの内容と完全一致する内容にしています。
- 各条件で両版を1回ずつウォームアップし、実行順を交互に入れ替えて各7回の `br --dry-run` 全体を計測。ビルド・リポジトリ準備・トレース取得は計測外です。
- 標準出力・標準エラーをパイプで取得。計測中は他のテストやビルドを実行していません。

### 結果

| ブランチの状態 | 変更前の中央値 | 変更後の中央値 | 候補数（両版） |
| --- | ---: | ---: | ---: |

| squash 済み10本 | 0.563秒 | 0.248秒 | 10 |

未マージ100本では約95%短縮しました。トレースで確認した追加判定の Git 起動数は、`merge-base` 100回と `diff-tree` 200回の計300回から、`rev-parse` 2回と `diff-tree --stdin` 1回の計3回になりました。この条件では共通祖先から既定ブランチへの同じツリー比較も100回から1回になっています。

各実行は正常終了し、両版の候補数は一致しました。各条件の計測前後でブランチ先端と作業ツリーに変化がなく、`FETCH_HEAD` が作成されていないことも確認しています。リモート照会は両版とも毎回1回です。通常マージ済みのブランチでは追加判定を実行せず、削除候補の操作直前の再確認は一括化していません。

この結果はローカル origin と上記の履歴・ファイル構成での実測です。実際の SSH 接続時間は別途加わります。変更パス数や履歴の構造によって所要時間は変わり、同じ速度を保証するものではありません。判定基準と安全性を維持する処理は [設計](design.md#リモート照会と履歴判定)、検証内容は [開発手順](../CONTRIBUTING.md#検証)を参照してください。

## コマンド全体の目標と5回の改善・検証

2026年11月3日 JST、「初回2秒未満・接続再利用時1秒未満」を目標に5回の改善・検証を実施しました。通信・判定・削除完了までを対象とし、5回で一旦停止しています。**接続再利用時は全4状態で達成しましたが、初回は未達です。**

1. macOS の Git 起動を計測。`/usr/bin/git --version` の15回の中央値は約12ms、`xcrun --find git` が選ぶ同じ Git 本体は約3msでした。Apple の起動用プログラムだけを一度解決する実装を採用し、20本削除の接続再利用時は中央値約1.30秒から約0.96秒になりました。
2. Git のプロトコル v2 / v0 を別接続で比較。`giclean` リモートの照会だけの比較では、v0 は初回約1.76〜1.78秒、v2 は約1.93〜1.96秒でした。明示設定を維持したうえで、SSH 自動適用時の既定を v0 にしました。
3. 接続共有時にも照会ごとのプロトコルが伝わるよう `SendEnv=GIT_PROTOCOL` を指定。変更前後の接続共有による比較への混入を避け、変更後だけを新規接続と再利用に分けて再計測しました。SHA-1 / SHA-256 と明示設定の維持も結合テストで確認しました。
4. 参照の多い `savings` の実リモートでも比較。照会だけの接続再利用時は v0 が約0.57〜0.59秒、v2 が約0.75〜0.78秒でした。一方、v0 でも初回の照会だけで約2.26秒の回があり、通信を含む初回2秒未満を達成したとは扱いません。
5. 全チェックとリリースビルドを確認後、下記の条件で最終計測しました。中央値だけでなく、各状態の全サンプルが目標未満であることを達成条件にしました。
